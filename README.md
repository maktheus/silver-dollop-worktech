# GuardApp — Runtime Environment Anomaly Detector

Incognia Mobile SDK challenge submission.

## Quick start

1. Open the project root in **Android Studio Ladybug (2024.2+)**.
2. Let Gradle sync finish (it downloads Gradle 8.9 automatically).
3. Connect a device or start an emulator.
4. Run the **app** configuration (`Shift+F10` / ▶).

> **No additional setup is needed.** `local.properties` is generated by Android Studio on first sync.

## Building from CLI

```bash
./gradlew assembleDebug            # build debug APK
./gradlew installDebug             # install on connected device
```

If `gradlew` is not executable: `chmod +x gradlew`

## Architecture

```
detection/
├── DetectionSignal.kt      — data class + Severity / SignalCategory enums
├── SecurityReport.kt       — aggregated result with risk score & isTampered flag
├── EnvironmentAnalyzer.kt  — interface: analyze(Context): List<DetectionSignal>
├── EnvironmentGuard.kt     — facade; runs all analyzers in parallel (coroutines)
└── analyzers/
    ├── EmulatorAnalyzer.kt       — AVD, Genymotion, Nox, BlueStacks
    ├── CloneAnalyzer.kt          — Dual Space, VirtualApp, App Cloner, etc.
    ├── VirtualizationAnalyzer.kt — Xposed/LSPosed, Frida, Cydia Substrate, Magisk
    └── SignatureAnalyzer.kt      — cert integrity, installer source, package name

ui/
└── MainActivity.kt         — launches guard, renders grouped signal report
```

### Adding a new detection domain

Implement `EnvironmentAnalyzer`, return `List<DetectionSignal>`, and add an
instance to the `analyzers` list in `EnvironmentGuard`. No other changes needed.

## Detection strategies

| Analyzer | Techniques |
|---|---|
| **EmulatorAnalyzer** | `Build.*` properties, hidden `SystemProperties` via reflection, QEMU/emulator file artifacts, `/proc/cpuinfo` CPU markers |
| **CloneAnalyzer** | Known clone-app package presence, file artifacts, secondary Android user UID (≥100 000), redirected `dataDir`, `/proc/self/maps` native library names |
| **VirtualizationAnalyzer** | Xposed / LSPosed file artifacts + ClassLoader probe, Frida server port probe (27042) + `/proc/net/tcp`, Cydia Substrate / Magisk files, `/proc/self/maps` patterns |
| **SignatureAnalyzer** | X.509 cert subject ("Android Debug" = debug key), SHA-256 hash vs expected, install source vs known stores, declared vs runtime package name |

### Stealth considerations

* Critical string constants (e.g. `"goldfish"`) are assembled from char arrays at
  runtime to defeat simple `strings`/grep extraction from the APK.
* Each analyzer is wrapped in `runCatching` so that any single probe failure
  (e.g. SELinux denying a `/proc` read) cannot silence the rest of the report.
* In release builds, ProGuard/R8 obfuscates all internal class and method names.
* For production hardening, move the most sensitive checks to a native (JNI/NDK)
  library — native code is significantly harder to hook with user-space frameworks.

### Production hardening checklist (out of scope for demo)

- [ ] Replace `EXPECTED_CERT_SHA256 = ""` in `SignatureAnalyzer` with your actual release cert hash.
- [ ] Move file-path and class-name constants to native code (JNI).
- [ ] Attest via [Android Key Attestation](https://developer.android.com/training/articles/security-key-attestation) for hardware-backed integrity proof.
- [ ] Back-end risk scoring so the device never reveals the detection threshold.
- [ ] Rotate detection heuristics server-side to stay ahead of bypass attempts.
