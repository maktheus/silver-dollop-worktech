detection/DetectionSignal.kt

DetectionSignal · SignalCategory · Severity

▼
data class imutável thread-safe

O átomo do sistema. Cada evidência detectada vira um DetectionSignal. Usa data class para equals/hashCode automáticos — os testes podem fazer contains(signal) sem boilerplate. Imutável por design: os analyzers rodam em paralelo e não devem compartilhar estado mutável. 

enum class SignalCategory(val displayName: String) {
    EMULATOR("Emulator"),

    SIGNATURE("Signature / Integrity"),

detection/EnvironmentAnalyzer.kt

EnvironmentAnalyzer — fun interface (SAM)

▼
fun interface SAM testável com lambda

Contrato único: recebe Context, devolve lista de signals. fun interface (SAM = Single Abstract Method) permite instanciar com lambda diretamente. Sem isso, testes precisariam de classes anônimas completas. 

// interface normal — precisa de boilerplate
val fake = object : EnvironmentAnalyzer {
    override fun analyze(ctx: Context) = listOf(signal)
}

// fun interface — instancia com lambda ✓
fun interface EnvironmentAnalyzer {
    fun analyze(context: Context): List<DetectionSignal>
}
val fake = EnvironmentAnalyzer { listOf(signal) }  // ✓
detection/SecurityReport.kt

SecurityReport — resultado imutável com computed properties

▼
data class computed properties sem backing field 
data class SecurityReport(val signals: List<DetectionSignal>) {

    // get() sem backing field → calculado toda vez, nunca stale
    val isTampered: Boolean
        get() = signals.any { it.severity != Severity.LOW }

    val riskScore: Int
        get() = signals.sumOf { signal ->
            when (signal.severity) {
                Severity.HIGH   -> 3
                Severity.MEDIUM -> 1
                Severity.LOW    -> 0
            }.toInt()  // .toInt() necessário — Kotlin 2.0 sumOf ambiguidade
        }
}

Armadilha Kotlin 2.0: sumOf tem overloads para Int e Long. O compilador não infere qual usar dentro do bloco when. Solução: .toInt() explícito no resultado.

detection/EnvironmentGuard.kt

EnvironmentGuard — Façade + Factory + Orquestrador assíncrono

▼
Façade Pattern Factory Method coroutines paralelas crash isolation 
class EnvironmentGuard private constructor(  // ← construtor privado
    private val context: Context,
    private val analyzers: List<EnvironmentAnalyzer>,
) {
    suspend fun generateReport(): SecurityReport = coroutineScope {
        val deferred = analyzers.map { analyzer ->
            async(Dispatchers.Default) {
                runCatching { analyzer.analyze(context) }.getOrDefault(emptyList())
            }
        }
        SecurityReport(deferred.awaitAll().flatten())
    }

    companion object {
        // Produção — lista hardcoded de todos os analyzers
        fun create(context: Context) = create(context,
            listOf(EmulatorAnalyzer(), CloneAnalyzer(), VirtualizationAnalyzer(),
                   SignatureAnalyzer(), RootDetector()))

        // Testes — injeta qualquer lista
        fun create(context: Context, analyzers: List<EnvironmentAnalyzer>) =
            EnvironmentGuard(context.applicationContext, analyzers)
    }
}

EmulatorAnalyzer — 4 camadas de detecção de emuladores

▼
Build.* SystemProperties (reflection) arquivos QEMU /proc/cpuinfo stealth charArrayOf

🔍 Build.* properties

FINGERPRINT, MODEL, HARDWARE, MANUFACTURER. Emulador AVD tem HARDWARE="goldfish" ou "ranchu".

🔒 SystemProperties via reflection

Classe @hide do Android. ro.kernel.qemu=1 está setado em todo emulador QEMU.

📁 Arquivos QEMU

/dev/socket/qemud, /dev/qemu_pipe, /dev/socket/genyd (Genymotion).

🖥️ /proc/cpuinfo

"goldfish" ou "qemu" no cpuinfo indica CPU virtual do QEMU.

// Stealth: "goldfish" nunca aparece literal no APK
// strings app.apk | grep goldfish → nada encontrado
val goldfish = charArrayOf('g','o','l','d','f','i','s','h').concatToString()
val cpuInfo = File("/proc/cpuinfo").readText().lowercase()
if (cpuInfo.contains(goldfish)) { /* EMULATOR signal */ }

🗡️ su binaries

9 paths onde o binário su aparece em dispositivos rooteados. Magisk monta em /sbin/.magisk/mirror/.

📱 Root management apps

Magisk, SuperSU, KingRoot etc. Visíveis via PackageManager (requer <queries> no manifesto).

⚙️ System properties

ro.debuggable=1, ro.secure=0, ro.build.type=eng. Só em builds de desenvolvimento.

💾 Writable /system

Em dispositivo limpo, /system é sempre read-only. Se canWrite() retorna true → remontado com root.

analyzers/VirtualizationAnalyzer.kt

VirtualizationAnalyzer — Frida, Xposed, Substrate

▼
Frida port 27042 /proc/net/tcp parser ClassLoader probe /proc/self/maps

Decodificação do /proc/net/tcp: IP é little-endian, porta é big-endian. Bug corrigido nessa sessão: porta Frida 27042 = 0x69A2, não 0x699A.

sllocal_addressrem_addressstsignificado
0: 0100007F:69A2 00000000:0000 0A ⚠️ Frida LISTEN
1: 0200007F:C350 0100007F:69A2 01 ✓ ESTABLISHED — ignorado
0100007F = bytes 01 00 00 7F → little-endian → 7F.00.00.01 = 127.0.0.1
69A2 = 6×16³ + 9×16² + 10×16 + 2 = 24576+2304+160+2 = 27042
0A = TCP_LISTEN (estado que confirma servidor aguardando conexão) 
// Parseamento correto — evita falsos positivos no rem_address
val fridaPortHex = "69A2"  // 27042 = 0x69A2  ← corrigido nessa sessão
val localPort = parts[1].substringAfter(":")  // coluna 1 = local
val state     = parts[3]                        // coluna 3 = estado
if (localPort.equals(fridaPortHex, ignoreCase = true)
    && state.equals("0A", ignoreCase = true)) { /* Frida */ }

🛡️ Ameaças em Detalhe

Como cada ataque funciona e como o SDK detecta

🪝

Frida — Instrumentação Dinâmica

HIGH ▼

Frida é um framework open source de instrumentação dinâmica. Permite interceptar e modificar qualquer função Java/Kotlin ou nativa em runtime, sem modificar o APK.

🔴 O ataque

Atacante conecta frida-server (daemon root, porta 27042) e injeta script JS que hookeia generateReport() para sempre retornar relatório limpo.

🟢 Nossa defesa

3 camadas: socket probe na porta 27042, parser de /proc/net/tcp procurando estado LISTEN, e varredura de /proc/self/maps por frida-agent.so.

// Script Frida que burlaria um SDK sem proteção:
Java.perform(() => {
  const Guard = Java.use('com.incognia.guardapp.detection.EnvironmentGuard');
  Guard.generateReport.implementation = async function() {
    return Java.use('com.incognia.guardapp.detection.SecurityReport')
      .$new(Java.use('java.util.ArrayList').$new());
  };
});
💉

Xposed / LSPosed — Hooking de Classpath

HIGH ▼

Xposed modifica o app_process do Android — o processo que inicializa toda aplicação. Injeta XposedBridge.jar no classpath de cada app antes do código rodar. 

// Módulo Xposed que desativa todas as detecções:
XposedHelpers.findAndHookMethod(
    "com.incognia.guardapp.detection.EnvironmentGuard",
    lpparam.classLoader,
    "generateReport",
    new XC_MethodReplacement() {
        protected Object replaceHookedMethod(MethodHookParam param) {
            return new SecurityReport(Collections.emptyList());
        }
    }
);

// Nossa detecção — classe acessível = Xposed ativo:
try { Class.forName("de.robv.android.xposed.XposedBridge") }
catch (_: ClassNotFoundException) { /* limpo */ }
🌱

Root / Magisk — Controle Total do Dispositivo

HIGH ▼

Magisk usa tmpfs para montar um filesystem virtual sobre o /system real, contornando o dm-verity (verificação de integridade do Android). Do ponto de vista do app, o sistema parece intacto.

🔴 O que root permite

Editar /etc/hosts, instalar CA customizado para MITM de HTTPS, ler banco de dados interno do app, rodar frida-server.

🟢 Nossas 4 defesas

su binaries em 9 paths, 12 root management apps via PackageManager, system props (ro.debuggable), e /system writable check.

👥

Clone Apps / VirtualApp — Identidade Paralela

HIGH ▼

Apps como Parallel Space criam um "Android virtual" dentro do processo deles. Seu app roda como um processo filho com UID diferente, sem saber que está em um container. 

// Android aloca UIDs por usuário: blocos de 100.000
// Usuário primário: 10000–99999
// Perfil de trabalho / clone: 110000–199999

val userId = Process.myUid() / 100_000
if (userId != 0) { /* rodando em usuário secundário */ }

// dataDir também revela o clone:
// Primário: /data/data/com.incognia.guardapp
// Clone:    /data/user/10/com.incognia.guardapp  ← UID 10
📦

APK Repackaging — Distribuição Modificada

MEDIUM ▼

O atacante descompila o APK com apktool, remove as proteções de segurança do SDK, recompila e redistribui. Precisa ressinar com uma chave diferente — geralmente o debug keystore padrão. 

# Processo de repackaging (15 minutos para um iniciante)
apktool d app-release.apk -o decompiled/
# edita decompiled/smali/... remove chamadas ao SDK
apktool b decompiled/ -o modified.apk
jarsigner -keystore ~/.android/debug.keystore modified.apk androiddebugkey

// Nossa detecção: subject do certificado X.509
// Debug key sempre: "CN=Android Debug, O=Android, C=US"

⚡ Fluxo Completo de Detecção

Do launch do app até a decisão do servidor — passo a passo

1

App inicia — MainActivity.onCreate()

lifecycleScope.launch { } — chama EnvironmentGuard.create(this) na Main thread

2

generateReport() — 5 coroutines em paralelo

Cada analyzer recebe async(Dispatchers.Default) — I/O de /proc/* não bloqueia a UI

3

Cada analyzer executa suas verificações

EmulatorAnalyzer: Build.* + reflection + /proc/cpuinfo | RootDetector: su + props + writable | etc.

4

runCatching isola crashes

Se um analyzer lança exceção → getOrDefault(emptyList()) — os outros continuam normalmente

5

awaitAll().flatten() agrega tudo

List<List<DetectionSignal>> → List<DetectionSignal> — todos os signals numa lista plana

6

SecurityReport criado

isTampered = any { severity != LOW } | riskScore = Σ(HIGH×3 + MEDIUM×1)

7

UI renderizada por severidade

HIGH (vermelho) → MEDIUM (laranja) → LOW/INFO (azul) — agrupados e coloridos

8

Servidor Incognia decide

O SDK não bloqueia localmente — envia riskScore + signals para o servidor. Decisão fica no backend, fora do alcance do atacante.
